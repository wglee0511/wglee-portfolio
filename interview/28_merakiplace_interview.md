### Q4. 기억에 남는 프로젝트를 소개해 주세요.

> 근거: 후기 2023/09 · 2024/03

**→ 루티너리 메모리 문제입니다. 실사용자 지표에서 찾아 Peak Memory P95를 958.5MB에서 297.4MB로 줄였습니다.**

```
찾기  : 실사용자 지표에서 튄 버전 확인 → 같은 화면 반복 진입 → 메모리가 계단처럼 오름
고치기: SharedValue 정리 누락이 원인 → 언마운트 때 cancelAnimation을 일괄 호출하는 공용 훅 (값 24개)
확인  : 같은 방법으로 재측정 → P95 958.5 → 297.4MB, Android Native Heap -69%
```

**→ 배운 점은 "재고, 고치고, 같은 방법으로 다시 잰다"입니다.** 이미지 캐시를 의심했지만 숫자가 아니라고 해서 다른 원인을 찾았습니다.

> 근거: 후기 2025/10 (CTO가 지원을 신중히 고민해 달라고 당부) · 공고

**→ 지금 이 팀이 겪는 문제를 제가 해온 일로 바로 풀 수 있다고 봐서입니다.**

**→ 책·영화:** **[ 실제로 최근 본 것 하나 + 일에 가져온 생각 한 줄 ]** 지어내면 꼬리 질문에서 드러납니다.

### Q14. 스타트업에서 속도와 품질이 부딪히면 어떻게 하나요?

> 근거: 후기 2024/04 (일처리 속도를 반복 질문 — 2차에서 나왔지만 1차에서도 나올 수 있음) · 공고(스프린트 단위 오너십)

**→ 되돌리기 쉬운 건 빨리 내고, 되돌리기 어려운 건 느려도 확인합니다.** 기준은 하나입니다.

**→ 되돌리기 쉬운 것:** 화면 · 문구 · 실험 기능. 앱 코드만 바뀌는 건 CodePush(스토어 심사 없이 JS 교체)로 빠르게 내보냅니다. **되돌리기 어려운 것:** 결제 · 데이터 이전 · 네이티브 변경. 이건 PR에 따로 표시하고 실제 기기에서 확인합니다.

**→ 한계:** 지금 팀의 배포 구조(Feature Flag, 버전별 배포)는 공고 문구로만 알고 있어서, 역질문(Q18)으로 확인합니다.

# 4. AI 활용 — 1차에서는 가볍게

> 후기에는 AI 질문이 **기술 면접(2025/10)** 에서 나왔습니다. 1차에서도 공고의 핵심이라 한두 개는 나올 수 있어 짧게만 준비합니다.

### Q15. AI를 일에서 어떻게 쓰고, 결과물의 품질은 어떻게 보장하나요?

> 근거: 후기 2025/10 (AI 활용 질문) · 공고(AI-Native · AI Tool 지원)

**→ 사람이 매번 확인하던 걸 기계가 강제하게 만들어서, 쓰는 속도와 품질을 같이 잡았습니다.**

```
파일 수정 → ESLint 자동 수정
작업 종료 → 타입 검사 실패 시 못 끝남 (기존 에러 367개라 "편집한 파일"만 검사)
리뷰 에이전트 → 실제 났던 크래시 패턴 검사 (고치는 도구는 안 줌, 보고만)
```

**→ 제가 보는 건 둘로 줄었습니다.** "이 코드를 내가 설명할 수 있나"와 "실제 기기에서 맞나". 결제처럼 되돌리기 어려운 코드는 PR에 따로 표시했습니다.

**→ 한계:** LLM을 앱 기능으로 넣어(RAG 등) 운영한 경험은 없고, 개발 도구로 써 왔습니다.

---

### Q16. AI가 틀렸는데 사람이 바로잡은 사례가 있나요?

> 근거: 후기 2025/10 (AI 활용 질문) · 추정(회의론자 질문)

**→ 사례로 답합니다.** **[ 시킨 일 → AI의 첫 답 → 내가 의심한 이유 → 확인 방법 → 실제 원인 ]**

**→ 사례가 안 떠오르면 iOS 알림 사례를 쓰세요.** 알림이 버벅일 때 AI는 JS 렌더를 의심했지만, JS 프로파일러에 문제가 없어서 다른 경로로 바꿔 보니 사라졌고, 원인은 라이브러리가 메인 스레드에서 알림을 동기로 예약하던 것이었습니다([26번 Q8](./26_wrtn_interview.md)).

**→ 책임은 커밋한 사람에게 있습니다.** 그래서 설명 못 하는 코드는 넣지 않습니다.

# 5. 역질문 — 1차에서 가장 중요한 부분

**→ 1차는 회사가 상황을 설명하고 지원자가 판단하는 자리라서 질문의 질이 곧 평가입니다.** 2~3개만 고르세요.

### Q17. 마지막으로 질문 있으신가요?

> 근거: 후기 2025/10 (CTO가 상황을 설명하고 지원자의 판단을 구함) · 공고

**→ ① "팀에서 AI가 만든 코드는 어떤 기준으로 머지되나요?"** 하네스 경험과 이어집니다. AI 도구 비용 지원은 공고에 이미 있으니 묻지 말고, 사용 규칙이나 한계만 묻습니다.

**→ ② "Desktop 제품은 누가 쓰나요? 의사 · 약사용인가요?"** 공고에 App · Web · Desktop이 같이 있어서 묻습니다.

**→ ③ "Python/Django 레거시에서 옮기는 기준은 무엇인가요?"** 또는 "프론트엔드의 가장 큰 병목은 빌드 · 배포 · 협업 중 어디인가요?"

**→ ④ "이 포지션에서 첫 3개월에 기대하시는 성과는 무엇인가요?"** 입사 후 목표(Q12)와 이어집니다. 연봉 · 스톡옵션은 처우 협의 단계에서 묻습니다.

---

### Q18. (추가) 아직 지원을 고민 중인 이유가 있나요? 다른 곳과 비교한다면 어떤 기준인가요?

> 근거: 후기 2025/10 (지원을 신중히 고민해 달라는 당부) · 추정

**→ 기준은 세 가지입니다. ① 사용자 규모가 있는 제품인가 ② AI를 개발 방식에 깊게 쓰는가 ③ 기반(배포 · 모니터링)을 맡길 사람이 필요한가.** 이 팀은 셋 모두 공고에서 확인되는 곳입니다.

**→ 다른 곳과 비교 중인지는 사실대로 답합니다.** **[ 다른 진행 중인 전형 ]** 없다면 "여기에 집중하고 있다"고 말합니다. 거짓 경쟁 오퍼는 말하지 않습니다.

## 면접 전에 할 것 5가지

1. **나만의닥터를 직접 써 보기.** 진료 신청부터 약 배송까지 흐름을 따라가며 불편한 점 하나, 좋은 점 하나를 적어 둡니다. (Q10)
2. **`[ ]` 채우기.** 앱 3개 기간 · 재직과 겹치는지 · 기계공학에서 개발로 옮긴 이유 · 책/영화 · 추천인. 안 채우면 그 자리에서 막힙니다.
3. **프로젝트 소개 두 개를 1분씩 소리 내어 연습.** 메모리 문제(Q4)와 Cadence(Q6). 첫 문장은 결론 하나입니다.
4. **역질문 2~3개 고르기.** (Q17)
5. **공고에 있는 약점 셋을 소리 내어 말해 보기.** Django · 대용량 트래픽 · Mixpanel. 숨기지 않고 가까운 경험으로 잇는 연습입니다. (Q11)
