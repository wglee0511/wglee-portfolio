## 답변 준비 팁

**수치는 조건과 함께 말하세요.**
"메모리 69% 줄였습니다"보다 **"안드로이드 네이티브 힙 기준으로 개선 전후를 재봤더니 69% 줄었습니다"** 가 훨씬 신뢰를 줍니다.
콜드 스타트 20%대 개선도 *"디버그 빌드에서 열 번 측정한 중앙값 기준"* 이라고 먼저 밝히는 편이 좋습니다.
조건을 먼저 말하면 신뢰를 얻고, 숨기면 되물었을 때 곤란해집니다.

**"왜 그 값인가"를 준비하세요.**
지연 시간, 임계값, 개수 제한 같은 숫자는 자주 "왜 그 값이죠?"로 이어집니다.
근거가 기억나지 않으면 *"그때는 이런 기준으로 정했는데, 지금 보면 다시 검토할 만합니다"* 가 좋은 답변입니다.

**모르면 모른다고 하세요.**
"지금 보니 그 부분은 개선이 필요해 보입니다"는 감점이 아니라 가점입니다.
없는 근거를 만들어내는 것이 가장 위험합니다.

**하나의 경험을 세 가지로 말할 수 있게 준비하세요.**
같은 일도 ① 기술적 판단 ② 협업 과정 ③ 배운 점 으로 나눠 말할 수 있으면
어떤 각도의 질문에도 대응됩니다.

## 참고 ① — 이력서와 코드가 다른 부분 (루티너리)

`routinery-v2` 저장소를 전 브랜치까지 확인한 결과입니다. **이제 사실관계가 확정됐습니다.**

### ⚠️ 표현을 반드시 고쳐야 하는 3건

| 이력서 표현 | 실제 | 면접에서 이렇게 |
|---|---|---|
| 타이머 기록 **200개 링 버퍼로 제한** | **미구현.** 설계 문서만 존재 | "설계·제안까지 했다" |
| 루틴 이력 **18개월 윈도우로 캡** | **미구현.** 설계 문서만 존재 | "설계·제안까지 했다" |
| 화면 **50개 지연 로딩** | **구현 후 제거됨.** 현재 전부 정적 import | "측정하고 되돌렸다" |

**1·2번** — `docs/superpowers/specs/2026-06-11-memory-leak-fixes-design.md`에 **원인 분석과 설계가 상세히 남아 있습니다.**
Xcode Instruments로 두 가지 원인을 분리하고, 원본 데이터는 보존하되 메모리 전개 범위만 제한하는 방향까지 정리돼 있습니다.
**"구현했다"만 아니면 오히려 좋은 소재**입니다. 답변은 `09_tech_state.md` Q9 참고.

**3번이 가장 위험합니다.** 실제 이력은 이렇습니다 —
설계 문서 → 측정 인프라 구축 → 화면 62개 lazy 전환 → **프로덕션 베이스라인 측정용으로 임시 제거** →
복구 → **최종 제거**(`d3c2a5fc2`, 2026-06-02, 본인 커밋). 이 제거가 `dev`에 머지되어 **현재 배포 상태**입니다.

> **"50개 화면을 지연 로딩했습니다"에서 멈추면 안 됩니다.**
> 코드를 확인당하는 순간 콜드 스타트 수치(-24.4% / -21.8%)까지 전부 의심받습니다.
> 대신 **"측정해보고 내 작업을 되돌렸다"** 로 가면 훨씬 강한 카드가 됩니다.
> 커밋 히스토리에 측정→판단 과정이 그대로 남아 있어 **증명도 됩니다.**
> 답변은 `08_tech_react_native.md` Q5, `13_answers_experience.md` Q38 참고.

### 숫자가 어긋난 항목

- **SharedValue 25개 → 실제 24개** (온보딩 슬라이드 14 + 타이머 서클 6 + 비교 4). 문서는 24로 수정해 뒀습니다.
- **위젯 4종 → 실제 5종** (Grid · Calendar · Weekly · Streak + **CheckList**).

### 표현만 조정한 항목

- **"React Query Selector 패턴 전면 적용"** — React Query의 `select` 옵션은 **코드에 없습니다.**
  Zustand 부분 구독과 파생 상태 정리로 말하세요.
- **"hydration 완료 후 마이그레이션 순서 보장"** — `onRehydrateStorage`를 쓴 코드는 없습니다.
  대신 **스토어별 version/migrate**와 **MobX→Zustand 일회성 마이그레이션**이 실재하니 그걸로 말하세요.
- **타임라인 20MB 누수 수정** — 커밋(`030c607ba`)은 실재하나 **아직 `dev` 미머지**입니다.
  "해결했다"보다 "수정해서 올려둔 상태"가 안전합니다.

### 반대로, 코드가 이력서보다 강한 항목

면접에서 **먼저 꺼내면 좋은** 것들입니다. 이력서에는 없거나 축약돼 있습니다.

- **ANR 수정** — 이벤트 로깅 함수가 SDK 6개 + I/O 2개를 동기 호출해 메인 스레드를 0.5~2초 블로킹.
  `InteractionManager`로 분리. → `08_tech_react_native.md` Q4-1
- **CodePush 자체 구축 + 데이터 유실 방어** — CloudFront 캐시로 히스토리를 읽다 **전체 배포 이력이 날아갈 뻔한 것**을
  S3 원본 읽기 + 상위집합 검증으로 막음. → `13_answers_experience.md` Q86

- **Codex 이중화** — 복사가 아니라 **심볼릭 링크·동일 스크립트 참조**로 어긋나지 않게 만든 구조.

## 참고 ② — 이력서와 코드가 다른 부분 (페이히어)

`payhere-pos-rn` 저장소를 직접 확인한 결과입니다.

**코드로 확인된 것**

- Pusher 기반 실시간 채널 ✅ — `store/modules/push/` + `store/modules/payhereFront/`
- 고객 대면 앱 연동(서명 · 고객 로그인 · 현금영수증 정보) ✅ — `payhereFront` 모듈 564줄
- 네이버 예약 연동 ✅ — `store/modules/naverConnection/` 728줄
- 고객 관리 / 매출 분석 ✅ — 웹뷰 기반 (`CUSTOMER_MANAGEMENT_URL`, `SALES_ANALYSIS_WEBVIEW_URL`)
- 스탬프 적립 ✅ — `stamp_options` 결제 payload, `ModifyCategoryAccumulationContents` 등
- Firebase Analytics 기반 행동 분석 ✅ — `middlewares/eventLogger.js`
- Redux Thunk · Saga ✅ — 둘 다 미들웨어로 등록
- Fastlane ✅ — `android/fastlane/Fastfile`, `ios/fastlane/Fastfile` (`firebase_stg` / `firebase_prd` lane)
- Firebase App Distribution ✅ — 안드로이드는 활성, **iOS는 주석 처리**되어 빌드까지만 돌아감

**이 저장소에서 확인되지 않는 것**

| 이력서 기재 | payhere-pos-rn |
|---|---|
| TypeScript | ❌ 전부 `.js` (`jsconfig.json`, TS 의존성 없음) |
| Redux Toolkit | ❌ `redux-actions` + `redux-pender` |
| Electron | ❌ 없음 |
| Next.js | ❌ 없음 |

이건 **이력서가 틀렸다는 뜻이 아니라**, 그 기술들이 다른 저장소(고객 대면 앱, 온라인 스토어 웹, 프론트 단말기)
경험일 가능성이 높다는 뜻입니다. **"어느 프로젝트에서 쓰셨죠?"에 저장소 단위로 답할 수 있게** 매핑해 두세요.

**⚠️ 가장 중요한 것 — 커밋 히스토리가 없습니다.**
`payhere-pos-rn`에는 커밋이 1개(`chore: 세팅`)뿐입니다.
즉 **어느 코드가 본인 작업인지 코드로 증명되지 않습니다.**
본인 기여를 ① 처음부터 만든 것 ② 크게 고친 것 ③ 읽고 이해만 한 것 으로 나눠서
면접 시작 시 스스로 선언하고 들어가세요. 자세한 문장은 `06_payhere_pos_answers.md` 맨 위에 있습니다.
